**Android and iOS: opening a streamed Web Publication no longer probes every chapter before the reader appears.**
The reader asked every chapter for its length up front — at least one HEAD request per chapter before first paint, which could stall opening large books over the network. Positions for streamed publications are now computed with zero network requests, trading byte-precise progress for one step per chapter; `Locator.totalProgression` for such publications is therefore chapter-granular, which consumers treating it as fine-grained input (for example remapping a stored lastmark onto changed content) should expect. On iOS, the navigator's `preloadPreviousPositionCount`/`preloadNextPositionCount` are measured in positions, so for streamed publications they now correspond to chapters rather than pages — lower them if bandwidth or memory is a concern. Publications stored as local files are unchanged and keep precise progress.
